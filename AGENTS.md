# Agent Workflow

## Before Starting Work

- Check open issues and PRs before creating a new issue, branch, or implementation plan.
- If any part of the requested work overlaps with an existing issue, do not duplicate it.
- If the existing issue already covers the work, comment there with the intended scope, current branch, and resolution direction.
- If the work is a subset of a larger issue, create a sub-issue or linked issue and reference the parent issue clearly.
- Prefer branch names that include the issue number, such as `codex/issue-123-short-description`.
- If an existing PR or branch is already in progress, continue from that work or document the conflict before starting a parallel implementation.

## Issue Quality

- Do not file bare issues that only state the problem.
- Include context, evidence, a short resolution direction, and acceptance criteria.
- For App Store, privacy, permissions, HealthKit, local networking, or compliance work, cite Apple official documentation when possible.

## Pull Requests

- Link the issue being addressed.
- State which existing issues or PRs were checked for overlap.
- Note the branch ownership path when the branch was created for a specific issue.
